# Asking an architectural question

If you have an architectural question that you need help with, or you think that the issue you are working on demands architectural decisions to be made, you can ask a question to get help from the team.

To ask a question, create a new issue in the repository and use the `question` label. Make sure to provide as much context as possible in the issue description, including any relevant code snippets, diagrams, or references to documentation.
Include labels for all relevant scopes (e.g., `backend`, `frontend`, `ml`, `devops`) to ensure the right people see your question.

> E.g. if your question is about the communication between the backend and the inference service, you should label your question with both `backend` and `ml` labels.

All discussion surrounding the question should be done in the issue comments. Once the question is resolved, the issue should be closed.
If the question results in architectural decisions being made, those decisions should be documented in an ADR, and the whole codebase workflow should be
followed.

See:

- [Issue assigned to issue resolved](improving-codebase.md) for more details on the codebase workflow.
- [ADR: Architectural Decision Records](../adr/README.md) for more details on how to write an ADR.
